System Overview

1. Why Visflow Was Built & System Architecture

In modern AI development, composing LLMs, prompt templates, API webhooks, and logical conditional filters requires a flexible, visual drag-and-drop workspace. However, executing such pipelines safely requires absolute mathematical guarantees: the graph MUST be a Directed Acyclic Graph (DAG) to prevent infinite loops, and developers must be able to add new node types rapidly without repeating boilerplate JSX.

💡 Core Architecture Decision: Separation of Concerns
The frontend strictly acts as the visual designer and in-memory state manager, while the backend acts as the authoritative graph theory validator and pipeline parser. This decoupling allows the backend to validate pipelines from any client (web, CLI, API) independently.
Design Pattern

2. Part 1 — Declarative Node Abstraction (`BaseNode` & `createNode`)

The Problem: In standard node-based apps, each new node type (Input, Output, LLM, Filter, API, Math) requires hand-writing 40+ lines of identical JSX: card wrappers, header labels, inputs, delete buttons, and manual coordinate math for input/output handles.

❌ Traditional Approach (Repetitive Boilerplate)

Each node requires full React JSX, manual CSS classes, state subscriptions, and error-prone handle spacing formulas duplicated in 10+ files.

✅ Visflow Declarative Factory Pattern

Adding a new node is pure data entry (~10 lines of config). Layout, delete handlers, accent borders, and handle math are generated automatically.

frontend/src/nodes/extraNodes.js — FilterNode Declaration JavaScript 
import { createNode } from './createNode';

// That's it! 10 lines defines the complete component with inputs, handles, and styling:

  title: 'Filter',
  icon: '🔍',
  accent: '#f59e0b',
  fields: [
    { name: 'condition', label: 'Condition', type: 'text', defaultValue: 'value > 0' }

  targetHandles: [{ id: 'input' }],
  sourceHandles: [{ id: 'output' }],

3. Part 2 & 3 — Dynamic Text Node & Precision Font Measurement

Why was TextNode kept outside the generic factory? Because it possesses dynamic capabilities a static configuration cannot describe: live regex token extraction and glyph-level auto-sizing.

🏷️
Dynamic Variable Token Extraction
Regex /\{\{\s*([A-Za-z_$][A-Za-z0-9_$]*)\s*\}\}/g parses variables in real-time. Each unique token automatically spawns a dedicated left-side input Handle on the node!
📐
Canvas Glyph-Width Measurement
Naive char.length * 8 assumes monospace and breaks on proportional fonts or emojis. Visflow measures rendered glyphs via an offscreen HTML5 2D Canvas context for perfect node wrapping.
🛡️
Test Environment Hardening
Equipped with intelligent environment guards that detect Node.js / jsdom test environments, preventing virtual console errors during unit test execution.
Graph Theory

4. Part 4 — Kahn's Algorithm & Topological Sorter (O(V + E))

A pipeline that executes in an infinite loop will crash backend workers. To prevent this, Visflow employs Kahn's Algorithm for Directed Acyclic Graph (DAG) validation and execution ordering.

backend/main.py — Kahn's Algorithm Implementation Python 3 
def find_cycle_nodes_and_order(node_ids: List[str], edges: List[Dict[str, Any]]):
    # 1. Compute in-degree (number of incoming edges) for every node
    adjacency = {nid: [] for nid in node_ids}
    in_degree = {nid: 0 for nid in node_ids}

    for edge in edges:
        s, t = edge.get('source'), edge.get('target')
        if s in adjacency and t in adjacency:
            adjacency[s].append(t)
            in_degree[t] += 1

    # 2. Queue all roots (in-degree == 0)
    queue = [nid for nid in node_ids if in_degree[nid] == 0]
    removed_order = []
    removed_set = set()

    # 3. Iteratively peel off in-degree-0 nodes and decrement neighbors
    while queue:
        curr = queue.pop(0)
        removed_order.append(curr)
        removed_set.add(curr)
        for neighbor in adjacency[curr]:
            in_degree[neighbor] -= 1
            if in_degree[neighbor] == 0:
                queue.append(neighbor)

    # Any node not removed is trapped in a circular cycle!
    stuck_nodes = [nid for nid in node_ids if nid not in removed_set]
    topological_order = removed_order if len(stuck_nodes) == 0 else []
    return stuck_nodes, topological_order

Why Kahn's Algorithm Over Recursive DFS?

  • No Recursion Depth Limit: Fully iterative queue-based approach prevents stack overflows on pipelines with thousands of steps.
  • Natural Execution Order: Directly yields the topological step-by-step execution timeline for valid graphs.
  • Precise Culprit Isolation: When a cycle occurs, it outputs the exact list of unresolvable nodes so developers can fix them immediately.
